# Shared — `@pop/shared` Workspace Package

## Runtime & Dependencies

- **Name**: `@pop/shared` — pnpm workspace package
- **No build step** — raw TypeScript consumed directly via path aliases
- **Consumers**: frontend (Expo/Metro), dashboard (Next.js), edge functions (Deno via relative path `../../../shared/*.ts`)
- **Only runtime dependency**: `zod` — no other runtime deps allowed

## Code Organization

```
shared/
  package.json           ← Package config (exports point to src/)
  tsconfig.json
  src/
    index.ts               ← Barrel export (14 modules)
    schemas.ts             ← Zod schemas + config types (not barrel-exported)
    database.types.ts      ← Auto-generated Supabase types (supabase gen types)
    nft.ts                 ← NFTType, NFTRarity, RARITIES, NFT_TYPES
    currency.ts            ← repairCost, breedCost, POOP token math
    xp.ts                  ← xpThreshold, applyXP, MAX_LEVEL
    cooldown.ts            ← calcCooldownHours
    energyDrain.ts         ← drain formulas
    breedProbabilities.ts  ← breed outcome math
    statPoints.ts          ← stat allocation, MAX_ENERGY
    lootRoll.ts            ← loot probability + hold logic
    minting.ts             ← initial NFT stat ranges
    degenBar.ts            ← bust/reward curve
    sensors.ts             ← sensor thresholds
    cloudRun.ts            ← Cloud Run config constants
    errors.ts              ← Canonical error codes for edge functions
```

## Patterns

### Barrel Exports

`index.ts` re-exports 14 modules. `schemas.ts` is not barrel-exported because it depends on Zod — import it directly:

```ts
import { NFTRarity, xpThreshold } from '@pop/shared'           // ✓ barrel
import { CurrencyConfigSchema } from '@pop/shared/schemas'      // ✓ direct
```

New modules must be re-exported from `index.ts` (unless they depend on Zod).

### Config-as-Code

All tunable game balance lives as exported constants in the source modules (e.g.
`REPAIR_COEF_A` in `currency.ts`, `XP_PER_USE` in `xp.ts`). There is no DB table
or runtime fetch — these constants are the authoritative source for game balance.

`schemas.ts` exports Zod schemas and inferred types (e.g. `CurrencyConfig`) for
each config section. These are consumed by the dashboard for what-if previews.

### The `cfg` Optional Parameter

All formula functions accept an optional typed `cfg` override. This lets tests and
the dashboard pass custom values while keeping code constants as the default:

```ts
export function xpThreshold(level: number, cfg?: XpCfg): number {
  const floor = cfg?.XP_FORMULA_FLOOR ?? XP_FORMULA_FLOOR
  return Math.max(floor, xpFormula(level, cfg))
}
```

**Convention**:
- Define the `cfg` type inline in the same file (avoids circular deps with `schemas.ts`)
- Use `??` fallback to the module-level constant

### Core Type System

```ts
export type NFTType = 'cruise-seat' | 'turbo-flush' | 'zen-fortress'
export type NFTRarity = 'common' | 'rare' | 'legendary' | 'transcendent'
```

## Pitfalls

- **Do not add a build step.** TypeScript is consumed raw via path aliases. Do not add a `dist/` or compile target.
- **Do not add runtime dependencies other than `zod`.** Any other runtime dependency breaks Deno edge function consumers.
- **Do not barrel-export `schemas.ts`.** Importing it from the barrel makes Zod a transitive dependency of every consumer.
- **Do not import `@pop/shared` from edge functions.** Use the relative path `../../../shared/*.ts` so public exports stay stable.
