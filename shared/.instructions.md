# Shared — `@pop/shared` Workspace Package

## Package Identity

- **Name**: `@pop/shared` — pnpm workspace package
- **No build step** — raw TypeScript consumed directly via path aliases
- **Consumers**: frontend (Expo/Metro), dashboard (Next.js), edge functions (Deno via relative path `../../../shared/*.ts`)
- **Only runtime dependency**: `zod` — no other runtime deps allowed

## Code Organization

```
shared/
  index.ts               ← Barrel export (14 modules)
  schemas.ts             ← Zod schemas + GAME_CONFIG_REGISTRY (NOT barrel-exported)
  gameConfig.ts          ← buildGameConfig() + FullGameConfig type (NOT barrel-exported)
  database.types.ts      ← Auto-generated Supabase types (supabase gen types)
  nft.ts                 ← NFTType, NFTRarity, RARITIES, NFT_TYPES

```

## Barrel Exports

`index.ts` re-exports 14 modules. **`schemas.ts` and `gameConfig.ts` are NOT barrel-exported** because they depend on Zod — import them directly:

```ts
import { NFTRarity, xpThreshold } from '@pop/shared'           // ✓ barrel
import { GAME_CONFIG_REGISTRY } from '@pop/shared/schemas'      // ✓ direct
import { buildGameConfig } from '@pop/shared/gameConfig'         // ✓ direct
import { buildGameConfig } from '@pop/shared'                    // ✗ will fail
```

New modules must be re-exported from `index.ts` (unless they depend on Zod).

## Zod-First Schema Convention

All tunable game balance is governed by `GAME_CONFIG_REGISTRY` in `schemas.ts`:

```ts
export const GAME_CONFIG_REGISTRY = {
  currency:     { schema: CurrencyConfigSchema,     defaults: CURRENCY_DEFAULTS },
  cooldown:     { schema: CooldownConfigSchema,     defaults: COOLDOWN_DEFAULTS },
  xp:           { schema: XpConfigSchema,           defaults: XP_DEFAULTS },
  // ... 11 keys total
} as const
```

**For each key**:
1. Import code defaults from the source module (e.g. `BREED_BASE_PRICE_USD` from `currency.ts`)
2. Define Zod schema with `.min()` / `.max()` safety bounds
3. Export `*_DEFAULTS` object built from those code constants
4. Register in `GAME_CONFIG_REGISTRY` with `{ schema, defaults }`

**Helper schemas** for common record shapes:
- `NFTRarityRecord<T>` — keyed by `common | rare | legendary | transcendent`
- `NFTTypeRecord<T>` — keyed by `cruise-seat | turbo-flush | zen-fortress`
- `DifficultyRecord<T>` — keyed by `easy | normal | strict`

## Adding a New Config Key

All three steps are **mandatory**:

1. **`schemas.ts`** — Zod schema, `*_DEFAULTS`, add to `GAME_CONFIG_REGISTRY`
2. **`gameConfig.ts`** — add the key to `FullGameConfig` type
3. **`supabase/migrations/`** — seed migration (see `supabase/.instructions.md`)

Without step 3, edge functions silently fall back to code defaults (no live tuning).

## The `cfg` Optional Parameter

All formula functions accept an optional typed `cfg` override. This lets edge functions pass DB-overridden values while keeping code defaults as fallback:

```ts
type XpCfg = {
  XP_FORMULA_BASE?: number
  XP_FORMULA_LINEAR?: number
  XP_FORMULA_QUADRATIC?: number
  XP_FORMULA_FLOOR?: number
}

export function xpThreshold(level: number, cfg?: XpCfg): number {
  const floor = cfg?.XP_FORMULA_FLOOR ?? XP_FORMULA_FLOOR
  return Math.max(floor, xpFormula(level, cfg))
}
```

**Convention**:
- Define the `cfg` type inline in the same file (avoids circular deps with `schemas.ts`)
- Use `??` fallback to the module-level constant
- Edge functions pass `config.<key>` from `buildGameConfig()`

## `buildGameConfig()` — Merge Logic

In `gameConfig.ts`, this function merges DB rows over code defaults:

```ts
buildGameConfig(rows) → { config: FullGameConfig, sources: ConfigSource, warnings: string[] }
```

- Starts with all code defaults
- For each DB row: validates via Zod schema, shallow-merges over defaults if valid
- Invalid rows → log warning, keep default (never crash)
- `sources` tracks `'db' | 'defaults'` per key (used by dashboard)

## `@migration` Annotations

Comments on constants indicate whether they can move to the `game_config` DB table:

- **`@migration: KEEP`** — structural invariant, NEVER move to DB. Examples: `MAX_LEVEL`, `MAX_ENERGY`, `RARITIES[]`, `NFT_TYPES[]`
- **`@migration: DELETE`** — should migrate to `game_config`. Examples: `REPAIR_COEF_A`, `BREED_BASE_PRICE_USD`, `XP_PER_USE`

## Core Type System

```ts
export type NFTType = 'cruise-seat' | 'turbo-flush' | 'zen-fortress'
export type NFTRarity = 'common' | 'rare' | 'legendary' | 'transcendent'
```

Always use these discriminated unions — never `string`. When pulling from DB, prefer Zod validation at boundaries over manual casting.
