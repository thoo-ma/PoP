# Dashboard — Next.js 15 (App Router)

## Runtime & Dependencies

- **Next.js 15** with App Router (`src/app/`)
- **Radix UI** primitives + **shadcn/ui** generated components in `components/ui/`
- **Tailwind CSS v3** — not v4. Do not use Uniwind or `@theme` syntax here.
- **Zustand 5** — client-side state management
- **class-variance-authority** (`cva()`) — used by shadcn components (not `tv()`)
- **echarts** via tree-shaken lazy wrapper (`components/LazyChart.tsx`)

## Code Organization

### Path Aliases (tsconfig)

```
@/*          → ./src/*              # e.g. @/components/ui/button, @/lib/utils
@pop/shared  → workspace package    # e.g. @pop/shared/xp, @pop/shared/schemas
zod          → ./node_modules/zod   # local Zod resolution
```

Note: `@pop/shared` is a pnpm workspace package — import sub-modules directly (e.g. `@pop/shared/xp`, `@pop/shared/schemas`).

### Layout

```
app/layout.tsx     → Root: fonts (Inter + JetBrains Mono), dark mode, AppShell
app/AppShell.tsx   → 'use client': SidebarProvider, game config fetch, error/warning banners
app/page.tsx       → redirects to /xp
app/<section>/     → individual config pages
```

## Patterns

### Styling — cn() + cva()

```tsx
// cn() is clsx + twMerge — defined in src/lib/utils.ts
import { cn } from '@/lib/utils'

// cva() for variant-based component styles (shadcn pattern)
import { cva, type VariantProps } from 'class-variance-authority'
```

**Do not use `tv()` (tailwind-variants) in the dashboard.** It is a `frontend/` pattern.

### shadcn/ui Components

All in `components/ui/`. Follow the existing pattern:
- Use `React.forwardRef<Element, Props>` for ref forwarding
- `cn()` to merge className overrides
- `displayName` set explicitly

```tsx
const Button = React.forwardRef<HTMLButtonElement, ButtonProps>(
  ({ className, variant, size, ...props }, ref) => (
    <button className={cn(buttonVariants({ variant, size, className }))} ref={ref} {...props} />
  )
)
Button.displayName = "Button"
```

### Code-Splitting

Charts are lazy-loaded to keep initial bundle small:
```tsx
import LazyChart from '@/components/LazyChart'
// echarts tree-shaken in src/lib/echarts.ts (Bar, Line, Radar only)
```

### Zustand Store — Game Config

`store/gameConfigStore.ts` manages all game config state:

```ts
interface GameConfigState {
  config: FullGameConfig        // validated config (always fully populated)
  sources: ConfigSource          // per-key: 'db' | 'defaults'
  drafts: Partial<FullGameConfig> // local edits not yet saved
  loading: boolean
  error: string | null
  warnings: string[]

  fetch: () => Promise<void>
  setDraft: <K>(key: K, value: Partial<FullGameConfig[K]>) => void
  clearDrafts: () => void
  clearDraftForKey: (key: GameConfigKey) => void
}
```

**Pattern**: Use `useShallow` for selector stability:
```tsx
import { useShallow } from 'zustand/react/shallow'
const { config, sources, drafts } = useGameConfigStore(useShallow((s) => ({
  config: s.config, sources: s.sources, drafts: s.drafts
})))
```

### Supabase Client

```ts
// src/lib/supabase.ts — nullable when env vars missing (SSG/build)
export const supabase = supabaseUrl
  ? createClient(supabaseUrl, supabaseAnon)
  : (null as unknown as ReturnType<typeof createClient>)
```

Always check `if (!supabase)` before making DB calls. The store handles this gracefully.

### Config Page Pattern

Each page follows:
1. `'use client'` directive
2. Import `useGameConfigStore` + `useShallow`
3. Import shared formulas (sometimes inlined to avoid .ts extension issues)
4. Compute derived values with `useMemo`
5. Render `Card` + `NumberInput` controls + `LazyChart` visualizations
6. Show `Badge` for source indicator (db vs defaults)

### Fonts

- **Inter** → `--font-inter` → body text (`font-sans`)
- **JetBrains Mono** → `--font-jetbrains-mono` → code/mono (`font-mono`)

## Pitfalls

- **Do not mix Tailwind versions.** This area is Tailwind v3 + `cva()`. The `frontend/` uses Tailwind v4 + `tv()`. Do not copy styling patterns between them, and do not introduce Uniwind or `@theme` syntax here.
- **Do not use `tv()` in the dashboard.** Use `cva()` for variants — it is the shadcn pattern.
- **Do not assume the Supabase client is non-null.** `supabase` may be `null` during SSG/build when env vars are missing. Always guard before calling.

## Skills & Agents
