## Runtime & Dependencies

- **React Native 0.81** with **Expo 55** (managed workflow, EAS builds)
- **React 19** — concurrent features available
- **HeroUI Native** (`heroui-native`) — primary UI component library
- **Uniwind** (Tailwind CSS v4) — styling via `className` on RN components
- **tailwind-variants** (`tv()`) — reusable style recipes in `styles/`
- **tailwind-merge** + `cn()` from `heroui-native` — className merging
- **React Native Reanimated 4** — animations (required by HeroUI Native)
- **@supabase/supabase-js** — backend communication
- **@pop/shared** — workspace package for game logic, types, schemas

⚠️ **This is Tailwind v4 (Uniwind) + `tv()`. The dashboard/ uses Tailwind v3 + `cva()`. Do NOT copy styling patterns between them.**

## Path Aliases

```
@/*          → ./           # e.g. @/components, @/hooks, @/screens
@pop/shared  → ../shared    # e.g. @pop/shared/xp, @pop/shared/schemas
```

Both `tsconfig.json` and `metro.config.js` define these aliases. Keep them in sync.

## Navigation

**React Navigation — Material Top Tabs** (horizontal swipe + tappable bottom icon bar).

- `App.tsx` wraps the app in `NavigationContainer` + `createMaterialTopTabNavigator`
- 5 tabs: Poop · Vault · Breed · Repair · Profile (declared directly in `App.tsx`)
- `PageIndicator` is the custom `tabBar` — renders icons/labels via React Navigation's tab bar props
- `types/navigation.ts` exports `RootTabParamList` for typed navigation

To add a new screen: add a `Tab.Screen` entry in `App.tsx`, add the route name to `RootTabParamList`, add its icon/label to `PageIndicator`.

## Styling — Uniwind + tv()

Uniwind (Tailwind v4) is configured in `global.css`:
```css
@import "tailwindcss";
@import "uniwind";
@import "heroui-native/styles";
@source "./components/**/*.tsx";
@source "./screens/**/*.tsx";
@source "./styles/**/*.ts";
@theme { /* custom color tokens */ }
```

**Rules**:
- Use `tv()` for any repeated className pattern — put recipes in `styles/`
- Use `cn()` from `heroui-native` (NOT from a local utils file) to merge classNames
- Color tokens defined in `constants/theme.ts` (70+ colors: stat, rarity, type, UI states)

Load the `tailwind-variants` and `uniwind` skills for detailed patterns and examples.

## Images

Use **`expo-image`** for all images — never `Image` from `react-native`.

`@/components/styled` provides two exports:

- **`RemoteImage`** — for remote URI images. Bakes in `cachePolicy="memory-disk"`, `transition`, and placeholder background automatically.
- **`Image`** — for static bundled assets (`require()`). Use `contentFit` only.

```tsx
import { RemoteImage, Image } from '@/components/styled'

// Remote URI — caching + transition + placeholder handled for you
<RemoteImage source={{ uri: url }} contentFit="cover" className="..." />

// Static asset
<Image source={require('@/assets/icon.png')} contentFit="contain" className="..." />
```

Placeholder color and transition duration are defined as named constants in `@/constants` (`IMAGE_PLACEHOLDER_BG`, `IMAGE_TRANSITION_DURATION`) and as `--color-image-placeholder` in `global.css`.

On load error `RemoteImage` sets `source` to `null`, leaving the placeholder background visible instead of showing a broken image indicator.

## App Variants

Three EAS build profiles map to three app variants via `APP_VARIANT`:

| `APP_VARIANT` | Bundle ID | Display name | EAS profile | Distribution |
|---|---|---|---|---|
| `development` | `com.popcorporation.pop.dev` | PoP (Dev) | `development` | Internal (Ad Hoc) |
| `preview` | `com.popcorporation.pop.prev` | PoP (Preview) | `preview` | Store (TestFlight) |
| _(unset)_ | `com.popcorporation.pop` | PoP | `production` | Store |

**Always set `APP_VARIANT` when running locally** — otherwise the bundle ID defaults to production:

```bash
# Dev client (most common for local iteration)
APP_VARIANT=development npx expo start --dev-client

# Preview variant locally
APP_VARIANT=preview npx expo start
```

The variant logic lives in `app.config.ts`. EAS remote builds set `APP_VARIANT` automatically via the `env` field in `eas.json`.

## Memoization

Wrap every exported component in `React.memo` unless it accepts `children` or reads context directly. This is the default — omitting memo requires a comment explaining why.

```tsx
export const MyComponent = memo(function MyComponent({ title }: Props) {
  return <Text className="text-lg font-bold">{title}</Text>
})
```

Stabilize callback props with `useCallback`. If a parent passes an inline arrow to a memoized child, the memo is negated.

## Accessibility

Every interactive element must have an `accessibilityLabel`. Every screen title must have `accessibilityRole="header"`. Dynamic status changes must be announced.

**Rules**:
- `Pressable`, `TactileButton`, `Button` → require `accessibilityLabel` (and `accessibilityHint` when the action isn't obvious)
- `Slider` → require `accessibilityLabel` + `accessibilityValue={{ min, max, now, text }}`
- `ScreenHeader`, `Dialog.Title`, section headings → `accessibilityRole="header"`
- Filter result counts, error banners, game phase changes → `accessibilityLiveRegion="polite"` or `AccessibilityInfo.announceForAccessibility()`
- Decorative images → `accessible={false}`

## List Rendering

Use `FlatList` (not `ScrollView` + `.map()`) for any list that can exceed ~10 items. ScrollView renders all items at once — FlatList virtualizes.

```tsx
// ✅ Virtualized
<FlatList data={nfts} numColumns={2} renderItem={renderItem} />

// ❌ Renders everything at once
<ScrollView>{nfts.map(nft => <NFTCard key={nft.id} ... />)}</ScrollView>
```

## State Management

**TanStack React Query** (`@tanstack/react-query`) for **server state** — all Supabase data (NFTs, detections, marketplace listings, profile stats). Provides automatic cache deduplication, invalidation, stale-while-revalidate, and retry.

- `QueryClientProvider` wraps the app at root in `App.tsx`
- `QueryClient` configured in `lib/queryClient.ts` (`staleTime: 30s`, `gcTime: 5min`, `retry: 2`)
- Query keys defined in `constants/queryKeys.ts` — always use these, never raw strings
- Query hooks return `{ data, loading, error, refetch }` for backward compat
- Mutation hooks use `useMutation` from React Query — do NOT manually reimplement loading/error/success state with `useState`
- Mutations call `queryClient.invalidateQueries()` on success — screens don't need manual refetch or event emitters

**React Context** for **client state** if needed — NOT Zustand (that's dashboard/).

**Never hardcode balance numbers** — always read from `config` via constants from `@pop/shared`.

**Custom hooks** in `hooks/` handle domain logic (auth, NFT operations, proof detection). Prefer hooks over inline logic in components.

## Dev Catalog

`components/dev/` provides a Dev Catalog accessible from the Profile tab in `__DEV__` builds. It exposes preview states that are hard or impossible to reach naturally (e.g. "fewer than 2 NFTs" breed guard, cooldown idle, all Poop game phases).

**When adding a new screen or UI state**, also add a preview entry:
1. Add mock data to `components/dev/devMockData.ts` if needed.
2. Add a render branch to `components/dev/DevPreviewRenderer.tsx` (key format: `section:description`).
3. Add the key + label to the matching `CatalogSection` in `components/dev/DevCatalog.tsx`.
