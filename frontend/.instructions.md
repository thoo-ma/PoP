# Frontend — React Native + Expo 55

## Runtime & Dependencies

- **React Native 0.81** with **Expo 55** (managed workflow, EAS builds)
- **React 19** — concurrent features available
- **HeroUI Native** (`heroui-native`) — primary UI component library
- **Uniwind** (Tailwind CSS v4) — styling via `className` on RN components
- **tailwind-variants** (`tv()`) — reusable style recipes in `styles/`
- **tailwind-merge** + `cn()` from `heroui-native` — className merging
- **React Native Reanimated 4** — animations (required by HeroUI Native)
- **@supabase/supabase-js** — backend communication
- **@pop/shared** — workspace package for game logic, types, schemas

## Code Organization

### Path Aliases

```
@/*          → ./           # e.g. @/components, @/hooks, @/screens
@pop/shared  → ../shared    # e.g. @pop/shared/xp, @pop/shared/schemas
```

Both `tsconfig.json` and `metro.config.js` define these aliases. Keep them in sync.

### Navigation

**React Navigation — Material Top Tabs.**

- `App.tsx` wraps the app in `NavigationContainer` + `createMaterialTopTabNavigator`
- 5 tabs: Poop · Vault · Breed · Repair · Profile (declared directly in `App.tsx`)
- `PageIndicator` is the custom `tabBar` — renders icons/labels via React Navigation's tab bar props
- `types/navigation.ts` exports `RootTabParamList` for typed navigation

To add a new screen:

- Add a `Tab.Screen` entry in `App.tsx`.
- Add the route name to `RootTabParamList`.
- Add its icon and label to `PageIndicator`.

## Patterns

### Styling — Uniwind + tv()

#### Three-layer design system

The frontend styling follows a three-layer model that maps cleanly onto how HeroUI Native and Uniwind work:

| Layer | Location | Job |
|---|---|---|
| **1 — Tokens** | `global.css` | Declares CSS variable *values* — brand colors (OKLCH), typography, spacing, radii, HeroUI semantic overrides. Single source of truth for every value. |
| **2 — Wrappers** | `components/ui/` | Wraps HeroUI Native components with PoP brand defaults baked in (tactile border, radius, etc.). The only place allowed to import from `heroui-native`. |
| **3 — Recipes** | `styles/` | `tv()` layout compositions — spacing, padding, flex arrangement — for screens and multi-component patterns. |

**The one invariant**: CSS variable *values* live only in `global.css`. Token *references* (`bg-surface-secondary`, `text-foreground`, etc.) may appear in any layer — wrappers, recipes, screens, or inline JSX. Change a value in one place, every reference updates automatically.

This maps directly onto HeroUI + Uniwind's own philosophy: HeroUI exposes all theming as CSS variables that you override in `global.css` (Layer 1); Uniwind treats token references as first-class citizens on any `className` prop (no restriction to a single layer); HeroUI's compound-component pattern is exactly what Layer 2 wrappers do.

**Rules**:
- Use `tv()` for any repeated className pattern — put recipes in `styles/`
- Use `cn()` from `heroui-native` (not from a local utils file) to merge classNames
- Color tokens defined in `global.css` `@theme` block (stat, rarity, type, UI states)

Load the `tailwind-variants` and `uniwind` skills for detailed patterns and examples.

### Images

Use **`expo-image`** for all images — never `Image` from `react-native`.

`@/components/styled` provides two exports:

- **`RemoteImage`** — for remote URI images. Bakes in `cachePolicy="memory-disk"`, `transition`, and placeholder background automatically.
- **`Image`** — for static bundled assets (`require()`). Use `contentFit` only.

```tsx
import { RemoteImage, Image } from '@/components/styled'

// Remote URI — caching + transition + placeholder handled for you
<RemoteImage source={{ uri: url }} contentFit="cover" className="..." />

// Static asset
<Image source={require('@/assets/icon.png')} contentFit="contain" className="..." />
```

Placeholder color and transition duration are defined in two places that must stay in sync: `@/components/styled` exports them as `IMAGE_PLACEHOLDER_BG` and `IMAGE_TRANSITION_DURATION`, and `global.css` exposes the color as `--color-image-placeholder`.

On load error, `RemoteImage` clears `source` so the placeholder background remains visible instead of rendering a broken-image indicator.

### HeroUI Native

Primary UI library for all UI components. Uses compound component pattern (`<Chip.Label>`, `<Button.StartContent>`, etc.). Load the `heroui-native` skill for component docs, props, and examples.

### Sanctioned UI wrappers (`components/ui/`)

Import HeroUI Native components from `@/components/ui` whenever a wrapper exists there. Wrappers bake brand defaults (radius, borders, tactile press, etc.) so consumers don't re-derive them. Biome `noRestrictedImports` warns on direct `heroui-native` imports outside `frontend/components/ui/**`.

- **Icon colour** — source from `useThemeColor('<token>-foreground')`, never hard-code.
- **Soft variants** — HeroUI exposes `bg-success-soft` / `bg-warning-soft` / `bg-accent-soft` (and `-foreground` pairs) as utilities, but most components ship only `danger-soft` as a variant prop. For other soft tones build from raw `View` / `Text` with the utilities; check the component's API before assuming a `*-soft` variant exists.
- **New wrappers** — add only when a 2nd consumer needs the same brand override.

### App Variants

Three EAS build profiles correspond to three app variants, selected at runtime by the `APP_VARIANT` env var:

| `APP_VARIANT` | Bundle ID | Display name | EAS profile | Distribution |
|---|---|---|---|---|
| `development` | `com.popcorporation.pop.dev` | PoP (Dev) | `development` | Internal (Ad Hoc) |
| `preview` | `com.popcorporation.pop.prev` | PoP (Preview) | `preview` | Store (TestFlight) |
| _(unset)_ | `com.popcorporation.pop` | PoP | `production` | Store |

**Always set `APP_VARIANT` when running locally** — otherwise the bundle ID defaults to production:

```bash
# Dev client (most common for local iteration)
APP_VARIANT=development npx expo start --dev-client

# Preview variant locally
APP_VARIANT=preview npx expo start
```

The variant logic lives in `app.config.ts`. EAS remote builds set `APP_VARIANT` automatically via the `env` field in `eas.json`.

### Memoization

Wrap every exported component in `React.memo` unless it accepts `children` or reads context directly. This is the default — omitting memo requires a comment explaining why.

```tsx
export const MyComponent = memo(function MyComponent({ title }: Props) {
  return <Text className="text-lg font-bold">{title}</Text>
})
```

Stabilize callback props with `useCallback`. If a parent passes an inline arrow to a memoized child, the memo is negated.

### Accessibility

Every interactive element must have an `accessibilityLabel`. Every screen title must have `accessibilityRole="header"`. Dynamic status changes must be announced.

**Rules**:
- `Pressable`, `TactileButton`, `Button` → require `accessibilityLabel` (and `accessibilityHint` when the action isn't obvious)
- `Slider` → require `accessibilityLabel` + `accessibilityValue={{ min, max, now, text }}`
- `ScreenHeader`, `Dialog.Title`, section headings → `accessibilityRole="header"`
- Filter result counts, error banners, game phase changes → `accessibilityLiveRegion="polite"` or `AccessibilityInfo.announceForAccessibility()`
- Decorative images → `accessible={false}`

### List Rendering

Use `FlatList` (not `ScrollView` + `.map()`) for any list that can exceed ~10 items. ScrollView renders all items at once — FlatList virtualizes.

```tsx
// ✅ Virtualized
<FlatList data={nfts} numColumns={2} renderItem={renderItem} />

// ❌ Renders everything at once
<ScrollView>{nfts.map(nft => <NFTCard key={nft.id} ... />)}</ScrollView>
```

### State Management

**TanStack React Query** (`@tanstack/react-query`) handles **server state** — all Supabase data (NFTs, detections, marketplace listings, profile stats). It provides automatic cache deduplication, invalidation, stale-while-revalidate, and retry.

- `QueryClientProvider` wraps the app at root in `App.tsx`
- `QueryClient` configured in `lib/queryClient.ts` (`staleTime: 30s`, `gcTime: 5min`, `retry: 2`)
- Query keys defined in `constants/queryKeys.ts` — always use these, never raw strings
- Query hooks return `{ data, loading, error, refetch }` for backward compatibility with the pre-React-Query call sites
- Mutation hooks use `useMutation` from React Query — do not manually reimplement loading/error/success state with `useState`
- Mutations call `queryClient.invalidateQueries()` on success — screens do not need manual refetch or event emitters

**React Context** for **client state** if needed. Do not add Zustand to the frontend — it is a dashboard-only dependency.

Never hardcode balance numbers — always read from `config` via constants from `@pop/shared`.

**Custom hooks** in `hooks/` handle domain logic (auth, NFT operations, proof detection). Prefer hooks over inline logic in components.

### Types

`frontend/types/` is reserved for **cross-cutting types consumed by 2+ unrelated modules** (e.g. `NFT`, `SortOption`, `ChallengeStatus`, `RootTabParamList`). Single-consumer types — component prop interfaces, hook return types, internal helper shapes — are **co-located** with their owning file. Cross-package contracts (RPC results, DB-derived types) live in `@pop/shared`.

Local types extend `@pop/shared` types for UI-specific additions:
```ts
import type { Tables } from '@pop/shared'

export type NFT = Omit<Tables<'nfts'>, 'user_id'> & {
  isListed?: boolean
  price?: string
}
```

### Constants, utils & lib

Same pattern as `types/`: cross-cutting items (2+ unrelated consumers) live in top-level folders; single-consumer items are co-located with their owner.

- `constants/` — app-wide configuration values & literal shared data (e.g. `queryKeys`, `SORT_OPTIONS`, `theme`, navigation). **Not** a home for formatters or helper functions.
- `utils/` — pure stateless helpers used by 2+ unrelated modules (e.g. `logError`, `formatDisplayName`, `getCooldownStatus`). React hooks and components do not belong here.
- `lib/` — third-party SDK initialization & HTTP/API wrappers around external services (Supabase client, React Query client, Edge Function wrappers, dev mocks).

### Dev Catalog

`components/dev/` provides a Dev Catalog accessible from the Profile tab in `__DEV__` builds. It exposes preview states that are hard or impossible to reach naturally (e.g. "fewer than 2 NFTs" breed guard, cooldown idle, all Poop game phases).

**When adding a new screen or UI state**, also add a preview entry:
1. Add mock data to `components/dev/devMockData.ts` if needed.
2. Add a render branch to `components/dev/DevPreviewRenderer.tsx` (key format: `section:description`).
3. Add the key + label to the matching `CatalogSection` in `components/dev/DevCatalog.tsx`.

## Pitfalls

- **Do not mix Tailwind versions.** This area is Tailwind v4 (Uniwind) + `tv()`. The `dashboard/` uses Tailwind v3 + `cva()`. Do not copy styling patterns between them.
- **Do not add Zustand to the frontend.** Zustand is a `dashboard/` dependency only — use React Query for server state and React Context for client state.
- **Do not import `Image` from `react-native`.** Use `expo-image` via `@/components/styled` (`RemoteImage` for URIs, `Image` for static `require()`).
- **Do not use `ScrollView` + `.map()` for long lists.** Use `FlatList` for anything that may exceed ~10 items.
- **Do not hardcode balance numbers.** Read them from `@pop/shared` config constants.
- **Do not skip memoization.** Wrap exported components in `React.memo` unless they accept `children` or read context directly.
- **Do not import HeroUI Native components directly.** Use `@/components/ui` — see `Sanctioned UI wrappers` above.
