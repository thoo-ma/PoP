# Supabase — Edge Functions & Migrations

## Runtime

- **Edge Functions**: Deno runtime (TypeScript). Deployed to Supabase Edge.
- **Migrations**: Raw SQL applied in order by filename timestamp.
- **Shared code**: Import from `../../../shared/*.ts` (relative path, NOT `@pop/shared`).

## Migration Naming

Timestamp prefix `YYYYMMDDHHMMSS_<description>.sql`:
```
supabase/migrations/20260327000000_decrement_poop_balance.sql
```

## Migration Rules

- Always use `TIMESTAMPTZ` (never `DATE` or `TIMESTAMP`)
- Always use `DEFAULT NOW()` (not `CURRENT_TIMESTAMP`)
- Always `ENABLE ROW LEVEL SECURITY` on new tables
- Add RLS policies immediately — never leave a table unprotected
- Use `CREATE OR REPLACE FUNCTION` for idempotent RPCs
- Use `IF NOT EXISTS` for `CREATE TABLE` when safe

## Seed Migrations for `game_config`

When a new config key is added to `shared/` (see `shared/.instructions.md`), a seed migration is **also required** here so the DB row exists for live tuning.

```sql
-- Pattern: DB values win on duplicate keys, defaults fill gaps
INSERT INTO public.game_config (key, value)
VALUES ('my_new_key', '{ ... }'::jsonb)
ON CONFLICT (key) DO UPDATE
  SET value = EXCLUDED.value || public.game_config.value;
```

**Without the seed migration**: edge functions silently fall back to code defaults (no live tuning), the dashboard shows `source: 'defaults'`, and admins cannot save overrides.

Reference: `migrations/20260305000001_seed_game_config.sql` seeds all original keys.

### Auth Pattern

Every edge function must:
1. Handle CORS preflight (`OPTIONS` → 204)
2. Extract JWT user: `supabase.auth.getUser()` → 401 if missing
3. Check ownership on every DB read/write: `.eq('user_id', userId)`

### Ownership Checks — Every Mutation, Not Just Queries

```ts
// ✅ Defence-in-depth: both SELECT and UPDATE check ownership
const { data } = await supabase.from('nfts').select('*').eq('id', nftId).eq('user_id', userId).single();
await supabase.from('nfts').update({ energy: 100 }).eq('id', nftId).eq('user_id', userId);

// ❌ NEVER trust just the NFT ID from the request body
const { data } = await supabase.from('nfts').select('*').eq('id', nftId).single(); // Missing user check
```

### Balance Mutations — Atomic RPCs

**Never** use read→check→write for `poop_balance`. Use atomic RPCs:
- `increment_poop_balance(p_user_id, p_amount)` — for earning POOP
- `decrement_poop_balance(p_user_id, p_amount)` — for spending POOP

These use `UPDATE ... WHERE poop_balance >= p_amount` with Postgres row-level locking to prevent race conditions.

### Logging Convention

Always prefix with function name and include user context:
```ts
console.log('breed-nfts: user', userId);
console.log('breed-nfts: cost breakdown — parent1 (...) → $100, parent2 (...) → $150, total $250');
console.error('breed-nfts: fetch parents error', fetchError);
```

### HTTP Error Semantics

| Status | Meaning | When |
|---|---|---|
| `400` | Bad Request | Missing required fields, malformed input |
| `401` | Unauthorized | No/invalid auth token |
| `402` | Payment Required | Insufficient POOP balance |
| `404` | Not Found | NFT doesn't exist or not owned by user |
| `422` | Unprocessable Entity | Valid input but business rule violation (energy 0, breed limit, audio too short) |
| `429` | Rate Limit / Cooldown | Daily detection limit or NFT cooldown |
| `500` | Internal Server Error | DB fault, Cloud Run error, unexpected exception |
